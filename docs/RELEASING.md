# 发布流程

1. 更新版本号、README 与 CHANGELOG。
2. 构建并运行相关测试，检查主队、日期、详情、滚动与错误状态，说明实机验证缺口。
3. 验证 APK 签名与已有发布包一致。维护者发布包沿用初始环境的 debug 签名，密钥仅保留本机；未来正式签名必须安排迁移，不能直接替换签名声称可覆盖更新。
4. 不提交本地设置、缓存、密钥或构建产物；提交源码，创建 `vX.Y.Z` 标签。
5. Release 附 APK、干净源码 ZIP、`SHA256SUMS.txt` 与准确说明；核对上传后校验值与下载链接。

CI 只构建和测试，其签名不等于维护者签名，Artifact 不作为覆盖更新包。不自动上传私有密钥，不重打包未知历史 APK。
